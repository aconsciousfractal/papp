# Organisation: make the next useful action visible

Use this for ordinary project or workspace organisation when no domain-specific
research or software evidence is needed. Start with what the person wants to
finish and the constraints that affect the next action.

Reuse the existing note, issue list, calendar or folder entry. Keep goal, current
state, materials and next action together, with the relevant owner. A short
answer can carry them inline. For shared or resumed work, use one accessible
checkpoint rather than competing status documents.

Separate an intended plan from work completed. “Waiting” names an actual
dependency; “finished” refers to the completion criterion. Cancelling an activity
does not prove its approach wrong. Record why a significant choice changed
when that reason will matter at the next handoff.

Create a folder or file when the work needs a durable home. A personal reading
project may need one note with links. A shared project may need a material
inventory and named responsibilities. Neither implies a bibliography graph,
scientific claim ledger or a prescribed number of subfolders.

Example: organise a small archive of meeting notes. Make an index of the
selected notes, identify missing dates explicitly and name the next sorting
action. Do not infer that a missing item never existed. Preserve original
content when reordering the index.

If the task is already a clear one-step action, do it and report the outcome;
no organisation module or additional file is necessary. If the material belongs
to another person or an external action lacks authority, defer that action
while preparing the parts already authorised. Do not claim a file was saved
when only its content was returned in chat.
