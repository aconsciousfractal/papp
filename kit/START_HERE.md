# PAPP — start with the work

Documentary guidance **PAPP/documentary-1.0.2** for research, software and
organised work. Delivery: **PAPP/github-1.0.2**.

Tell your assistant what you want to achieve, what materials you have and where
you want to work. You do not need to choose a protocol level or fill a form.

> Use this PAPP guide to help me with [goal]. Work in [location, if known].
> Start from what already exists, choose the guidance this work needs, and
> produce a useful first result with a clear place to resume.

## For the working assistant

1. Read [the short core](PAPP.md). Inspect the user's request and the existing
   project's entry, working instructions and current state before creating files.
2. For new standalone work selected by the user, use this guide's native
   account. Its scope and obligations are defined in [the working agreement](CONTRACT.md).
   If another contract already governs the project or a dependent result, keep
   it and consult [compatibility](COMPATIBILITY.md) before a replacement.
3. Infer the needed reading from the task. Open only the relevant modules below.
   Ask for missing decisive information while continuing independent authorised
   work. Do not turn ordinary startup into a questionnaire.
4. Deliver the useful result and [final handoff](PAPP.md), with the next action
   and applicable authorisation, or say that no further work is needed. For
   durable work, reuse one sufficient checkpoint in its existing home or follow
   [workspace setup](WORKSPACE.md).

| Work calls for | Read when needed |
| --- | --- |
| Implementing or changing software | [Software](modules/SOFTWARE.md) |
| Historical, textual or documentary research | [Documentary research](modules/DOCUMENTARY_RESEARCH.md) |
| Measurements, datasets or scientific inference | [Empirical research](modules/EMPIRICAL_RESEARCH.md) |
| Mathematical statements, calculations, certificates or proofs | [Mathematics](modules/MATHEMATICS.md) |
| Keeping an ordinary project or workspace organised | [Organisation](modules/ORGANISATION.md) |
| Finding sources, relationships or research routes repeatedly | [Optional atlas](modules/ATLAS.md) |

Combine modules when the question crosses domains. Their purpose is to obtain
the evidence the conclusion needs, not to complete every module's checklist.

Light means the core and a small native account. Research adds the relevant
source, observation and inference guidance. Rigorous adds the proof, replay,
review or engineering assurance the particular conclusion requires. These are
reading depths, not permission to lower necessary assurance.

For a brief explanation, the account can be inline. For shared or resumed work,
preserve the result and its checkpoint. An [example project note](examples/PROJECT_NOTE.md)
shows what this can look like without a separate ledger or atlas application.
