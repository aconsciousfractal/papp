# Contributing

Useful contributions include clearer instructions, broken-link fixes and
concrete improvements to the guides and examples. Start with the relevant
guide and [edition scope](EDITION.md). Small, focused changes are easier to review.

To report a problem, describe the edition, file or section, what you tried,
what you expected and what you observed. For an improvement, explain the
problem it addresses and the change you propose. The two issue templates
provide a starting point; a short clear account is enough.

For a pull request, explain what changed and how you checked it. Check links
from the delivered folder and preserve relevant conditions and limitations.
Distinguish observed results from assumptions and expected benefits. A new
example is not evidence of general effectiveness by itself.

Share only material you are entitled to make public. Remove confidential data
and use a small invented example when that is sufficient. Public issues are
not a private support channel.

Keep [MIT notices](LICENSE), source attribution and third-party rights intact.
Changes to guidance and its delivery need consistent edition identities and
an updated file inventory. A draft contribution does not update a published
release or migrate another person's project automatically.
